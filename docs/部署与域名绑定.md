# 部署说明与域名绑定指引

本文档说明如何把本项目部署到生产环境，并将域名 `https://www.removewatermarker.com` 绑定到站点。

## 1. 环境要求

| 项目 | 要求 |
| --- | --- |
| Node.js | 20.9 及以上（推荐 22 LTS） |
| 包管理器 | npm 10+ / pnpm 9+ |
| 运行环境 | 支持 Node.js 的任意平台（Linux / Windows Server / 容器） |

本地验证：

```bash
npm install
npm run dev     # 开发服务器，默认 http://localhost:3000
npm run build   # 生产构建
npm start       # 启动生产服务器
```

> Windows 用户若使用 PowerShell 执行命令，请确保终端使用 UTF-8 代码页（`chcp 65001`），
> 否则含中文的源文件在通过管道重定向时可能出现编码损坏。推荐直接使用 VS Code 或
> Windows Terminal，并保持文件读写统一走 UTF-8。

## 2. 环境变量

在项目根目录新建 `.env.local`（生产环境用 `.env.production`）：

```bash
# AdSense 出版商 ID，形如 ca-pub-0000000000000000
# 未配置时站点仍可正常访问，广告位显示占位提示
NEXT_PUBLIC_ADSENSE_CLIENT=ca-pub-xxxxxxxxxxxxxxxx

# 站点 canonical 域名（须与下方 DNS、sitemap 配置一致）
NEXT_PUBLIC_SITE_URL=https://www.removewatermarker.com
```

`NEXT_PUBLIC_` 前缀的变量会被内联到浏览器构建产物中，修改后需要重新执行 `npm run build`。
**不要**把 AdSense 账号密钥、GA4 测量 ID 等私密凭据放入该前缀的变量中。

## 3. 部署方式

### 3.1 Vercel（推荐）

1. 将代码推送到 GitHub / GitLab / Bitbucket 仓库。
2. 在 Vercel 控制台点击 **Add New → Project**，导入该仓库。
3. Framework Preset 选择 **Next.js**，其余保持默认。
4. 在 **Environment Variables** 中填入上节的两个变量（Production 与 Preview 环境都要填）。
5. 点击 **Deploy**。构建产物会输出到 `.next` 目录。

Vercel 会自动为 `*.vercel.app` 分配 HTTPS 证书。

### 3.2 自托管（Node.js 服务器）

```bash
npm ci --omit=dev=false
npm run build
npm start
```

建议用 PM2 守护进程：

```bash
npm i -g pm2
pm2 start npm --name monitor-protocol-docs -- start
pm2 save
pm2 startup   # 按提示配置开机自启
```

### 3.3 静态导出（可选）

站点全部内容为构建期可确定的数据，若需要纯静态托管（对象存储 / CDN），在 `next.config.ts` 中启用：

```ts
const nextConfig: NextConfig = {
  output: "export",
  trailingSlash: true,
  images: { unoptimized: true },
  // ...
};
```

启用后执行 `npm run build`，产物位于 `out/` 目录。

> 注意：静态导出模式下无法运行依赖服务端运行时的功能。当前站点的搜索、协议详情、
> 品牌页均为构建期生成，静态导出会正常工作。

### 3.4 Docker

在项目根目录创建 `Dockerfile`：

```dockerfile
FROM node:22-alpine AS deps
WORKDIR /app
COPY package.json package-lock.json ./
RUN npm ci

FROM node:22-alpine AS builder
WORKDIR /app
COPY --from=deps /app/node_modules ./node_modules
COPY . .
ENV NEXT_TELEMETRY_DISABLED=1
RUN npm run build

FROM node:22-alpine AS runner
WORKDIR /app
ENV NODE_ENV=production NEXT_TELEMETRY_DISABLED=1
COPY --from=builder /app/package.json ./package.json
COPY --from=builder /app/node_modules ./node_modules
COPY --from=builder /app/.next ./.next
COPY --from=builder /app/public ./public
EXPOSE 3000
CMD ["npm", "start"]
```

构建与运行：

```bash
docker build -t monitor-protocol-docs .
docker run -d -p 3000:3000 --env-file .env.production monitor-protocol-docs
```

## 4. 域名绑定（removewatermarker.com）

### 4.1 DNS 记录

在域名注册商处添加以下记录：

| 类型 | 主机记录 | 指向 | 用途 |
| --- | --- | --- | --- |
| A | `@` | 服务器公网 IP | 裸域名 |
| A | `www` | 服务器公网 IP | 主域名 |
| CNAME | `@` | `cname.vercel-dns.com` | （Vercel 托管时的替代方案） |
| CNAME | `www` | `cname.vercel-dns.com` | （Vercel 托管时的替代方案） |

> `A` 与 `CNAME` 记录不能在同一主机名上同时存在，请按实际托管方式二选一。

### 4.2 Vercel 绑定域名

1. 项目 → **Settings → Domains** → **Add**。
2. 分别添加 `removewatermarker.com` 与 `www.removewatermarker.com`。
3. Vercel 会给出需要添加的 DNS 记录值，按提示在域名商处配置。
4. 等待证书签发（通常 1–30 分钟）。

建议将 `removewatermarker.com` 设为主域名，`www` 301 跳转到 `www` 版本，避免重复内容。
若希望两个域名都指向站点，请确保两者都能正常访问，并在 `next.config.ts` 中添加：

```ts
async redirects() {
  return [
    {
      source: "/",
      destination: "https://www.removewatermarker.com/",
      permanent: true,
    },
  ];
}
```

### 4.3 自托管绑定域名

使用 Nginx 反向代理：

```nginx
server {
    listen 80;
    server_name www.removewatermarker.com removewatermarker.com;

    location /.well-known/acme-challenge/ {
        root /var/www/certbot;
    }

    location / {
        return 301 https://www.removewatermarker.com$request_uri;
    }
}

server {
    listen 443 ssl http2;
    server_name www.removewatermarker.com;

    ssl_certificate     /etc/letsencrypt/live/www.removewatermarker.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/www.removewatermarker.com/privkey.pem;

    location / {
        proxy_pass         http://127.0.0.1:3000;
        proxy_http_version 1.1;
        proxy_set_header   Upgrade $http_upgrade;
        proxy_set_header   Connection 'upgrade';
        proxy_set_header   Host $host;
        proxy_set_header   X-Real-IP $remote_addr;
        proxy_set_header   X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header   X-Forwarded-Proto $scheme;
    }
}
```

签发证书（以 Certbot 为例）：

```bash
sudo certbot --nginx -d www.removewatermarker.com -d removewatermarker.com
```

### 4.4 站点内 URL 同步

`src/data/site.ts` 中的 `url` 字段是所有 canonical、Open Graph 与 sitemap 的来源，
必须与实际域名一致：

```ts
export const siteConfig = {
  url: "https://www.removewatermarker.com",
  // ...
};
```

修改后需重新构建。同时确认：

- `src/app/sitemap.ts` 使用的 `siteConfig.url`
- `src/app/robots.ts` 中声明的 Sitemap 地址
- `src/app/layout.tsx` 的 `metadataBase`

三处均以 `siteConfig.url` 为准，无需重复修改。

## 5. 上线后验证清单

- [ ] 首页与协议详情页可正常访问，返回 200
- [ ] `https://www.removewatermarker.com/sitemap.xml` 可访问且包含全部协议页
- [ ] `https://www.removewatermarker.com/robots.txt` 存在并声明了 sitemap 地址
- [ ] 任意页面源代码中存在 `<link rel="canonical">` 且指向 `https://www.removewatermarker.com/...`
- [ ] 六个必备页面可访问：/about/、/contact/、/privacy/、/terms/、/disclaimer/、/ads/
- [ ] 移动端（375px 宽度）导航折叠正常，无横向滚动
- [ ] 页脚友情链接区块在移动端按两列排布
- [ ] 配置 `NEXT_PUBLIC_ADSENSE_CLIENT` 后广告脚本正常加载，并显示「广告」标识
- [ ] Cookie 同意横幅出现，选择「仅必要」后不加载个性化广告
- [ ] Google Search Console 提交 `sitemap.xml` 并验证所有权

## 6. 常见问题

**Q：构建报 `invalid utf-8 sequence` 错误？**
A：通常是源文件被以非 UTF-8 编码写回。用 `node -e "console.log(require('fs').readFileSync('文件路径','utf8').length)"` 校验，
或用 VS Code 右下角「编码 → 另存为 → UTF-8」重新保存。中文站点建议将编辑器默认编码固定为 UTF-8。

**Q：部署后样式丢失？**
A：检查是否遗漏了 `public/` 目录，或 CDN 缓存了旧的静态资源。

**Q：sitemap 里出现 `localhost`？**
A：`siteConfig.url` 未改为正式域名，重新构建即可。
